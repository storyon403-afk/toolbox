# 本地画面文字 OCR

2026-11-04：已完成 macOS 桌面 → Rust → FFmpeg → Vision → 预览、缓存与文字导出的本机流程。无需 API Key，不上传素材，不下载额外模型。使用 Apple [VNRecognizeTextRequest](https://developer.apple.com/documentation/vision/vnrecognizetextrequest) 的 accurate 模式和语言校正；默认中文与英文，可选英文、日文、韩文。

## 使用

1. `./LP build` 后重新打开应用，导入或下载视频。
2. 提取页右侧选择完整时长或开始/结束时间。
3. “画面文字 OCR”选择语言和间隔（默认 5 秒），点击“识别画面文字”。间隔须为 1–3600 秒，每次最多 300 帧；长视频需要增大间隔或缩短范围。
4. 完成后自动选择 OCR 文字来源。可预览、分页浏览或导出 TXT、Markdown、SRT。切换“文字来源”可查看独立保留的语音 / 导入文字。

OCR 不是逐帧字幕提取。每个采样点的文本暂以该点到下个采样点为时间区间，最后一区间截断到选区结束；连续相同的识别内容合并，空画面打断合并。可能漏识别短暂文字、多栏顺序可能有误，时间轴尤其是 SRT 需要人工校对。模型结果不会被当作指令执行。

## 数据与边界

- `ocr` 命令：活动 `asset_id`、可选 `range`、整数 `interval_ms`、语言 `zh/en/ja/ko`。不接受文件路径、工具路径或无水印结论。
- `content` 和 `export` 额外接受 `text_source: speech | ocr`，省略时兼容原有语音 / 导入文字。OCR 不覆盖语音转写，不存在自动回退混用。
- `doctor.ocr` 表示配置的本地 helper 文件存在；实际识别仍可能失败。`asset.has_ocr` 表示存在可用结果。
- 原生宿主指定应用包内 `linkparsing-ocr`。开发测试可通过可信环境变量 `LINKPARSING_OCR` 指定绝对路径，网页无此能力。
- 识别前校验源 SHA-256。私有 `ocr-*` 临时目录位于用户所选工作目录；每次仅保留一帧，缩放至最长边不超过 1920 像素，完成、失败和取消均清理。此缩放不等于解码器内存配额或 OS 沙箱。
- helper 的标准输出仅走私有 IPC，原始错误不会写入普通日志。单帧文本限制 64 KiB，总采样文本限制 4 MiB。媒体工具使用参数数组、进程组取消和既有工具超时。
- 结果以私有权限原子保存为 `.linkparsing-ocr-<SHA256>.json`，包含版本、摘要、语言、范围、间隔与文字。重新在相同工作目录导入同一素材或打开同一下载目录时恢复；不匹配或损坏缓存忽略。只保留该素材最近一次成功 OCR，重跑失败/取消保留旧结果。
- OCR 输出是文字，不受水印阻断；私有采样帧不作为视觉导出发布。画面、原视频仍必须通过独立人工审核，原视频仍保留完整时长。

## 验证

```sh
./LP build
python3 scripts/test-ocr.py
node scripts/test-ui.mjs
```

真实 Vision/FFmpeg 测试使用本机生成的中英文画面，覆盖识别、去重、独立文字来源、三种文字格式、未知水印仍阻断原视频、范围/语言校验、取消清理、缓存恢复与损坏忽略、空画面失败。桌面测试使用独立 Chromium 和真实 Rust IPC，文件选择器为测试替身，验证按钮、来源切换、导出内容与响应式布局。测试没有访问视频平台，不代表任意视频的识别准确率或旧版 macOS 兼容性验收。
